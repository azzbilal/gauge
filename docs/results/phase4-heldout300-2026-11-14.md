# Phase 4 benchmark, tightened: 300 held-out tasks (2026-11-14)

**Why.** The first Phase 4 run had 20 held-out tasks: 0/20 zero-shot and 6/20 few-shot,
with Wilson 95 % intervals about ±19 points wide. At temperature 0 every rollout repeats
the same answer, so more rollouts add nothing. More tasks do. This run uses 300 new
held-out tasks, stratified by family and hole pattern, with the model, prompt, settings and
five examples left the same.

Everything ran locally: Ollama `qwen3.5:9b-q4_K_M` and CadQuery 2.7.0 on Python 3.10.11.
No hosted model was used.

## 1. The new held-out batch

```bash
GAUGE_CAD_PYTHON=... python model/generate.py --count 300 --seed 1 --heldout 1 --stratify \
    --exclude model/data/synthetic-seed0-n100.json --out model/data/heldout-seed1-n300.json --check
```

- **All held out, disjoint from training.** All 300 tasks are held out. None shares a family
  and parameter set with any of the 100 seed-0 tasks (the 80 training tasks plus the old 20
  held-out tasks), and none shares its prompt and spec text with them.
- **Stratified.** 60 tasks per family, split evenly over each family's hole patterns:

  | Family | Cells |
  |---|---|
  | plate | corners 12, row 12, grid 12, circle 12, centre 12 |
  | box | none 15, corners 15, row 15, centre 15 |
  | bracket | row 20, corners 20, centre 20 |
  | cutout | none 60 |
  | rounded | corners 20, circle 20, centre 20 |
- **Composition shift.** 25 % of the tasks have no holes (75 of 300), against 30 % (6 of 20)
  in the old held-out set. Single-hole (`centre`) tasks are 22 %. The headline rate depends
  on this mix, so compare cells, not just headlines, with the 20-task run.
- **Controls.** `--check` scored every reference against its own rubric: 300/300 solved,
  executed. On the benchmark, `--mock oracle` scores 300/300 (Wilson 99–100 %) and
  `--mock wrong` (every box 7 mm wider) scores 0/300 (0–1 %), both `scoring executed`.

| | |
|---|---|
| Model | `qwen3.5:9b-q4_K_M` (Ollama, local) |
| Request | `/api/generate`, `think: false`, temperature 0, `num_ctx` 16384, `num_predict` 4096, 1 rollout |
| Few-shot examples | `--train-data model/data/synthetic-seed0-n100.json`: the same five train tasks as the 20-task run (`plate-001`, `box-001`, `bracket-001`, `cutout-001`, `rounded-001`), as recorded in the report's `generation.fewshot` |
| Only difference | the few-shot arm puts the five worked examples before the task |

The two batches reuse ids (`plate-001` exists in both). So with `--train-data` the harness
checks the examples against the evaluated set by family, parameters and text, not by id.

## 3. Results

### Few-shot K=5: 122/300 = 41 % (Wilson 95 %: 35–46 %)

The interval is now about ±5.5 points wide, down from ±19. There were no unjudged, not-run
or empty answers; 1 answer was cut off at `num_predict`.

| Family | Solved | 95 % Wilson |
|---|---|---|
| box | 30/60 (50 %) | 38–62 % |
| bracket | 0/60 (0 %) | 0–6 % |
| cutout | 60/60 (100 %) | 94–100 % |
| plate | 12/60 (20 %) | 12–32 % |
| rounded | 20/60 (33 %) | 23–46 % |

| Stratum | Solved | 95 % Wilson | Stratum | Solved | 95 % Wilson |
|---|---|---|---|---|---|
| box/none | 15/15 | 80–100 % | plate/centre | 12/12 | 76–100 % |
| box/centre | 15/15 | 80–100 % | plate/corners | 0/12 | 0–24 % |
| box/corners | 0/15 | 0–20 % | plate/row | 0/12 | 0–24 % |
| box/row | 0/15 | 0–20 % | plate/grid | 0/12 | 0–24 % |
| bracket/centre | 0/20 | 0–16 % | plate/circle | 0/12 | 0–24 % |
| bracket/corners | 0/20 | 0–16 % | rounded/centre | 20/20 | 84–100 % |
| bracket/row | 0/20 | 0–16 % | rounded/corners | 0/20 | 0–16 % |
| cutout/none | 60/60 | 94–100 % | rounded/circle | 0/20 | 0–16 % |

By hole pattern: none 75/75 (95–100 %), centre 47/67 (58–80 %, all 20 misses are
brackets), corners 0/67 (0–5 %), row 0/47 (0–8 %), circle 0/32 (0–11 %), grid 0/12
(0–24 %).

**What the larger set shows.** The 20-task finding holds and is now pinned down. With
examples, the model solves every task with no holes or a single centred hole, except
brackets. It solves **no multi-hole task in any family (0 of 158; 0 % to 2.4 %)** and no
bracket (0/60). The 20-task run could only say "0/14 with holes". The 300-task run splits
that into single-hole tasks (solved) and multi-hole tasks (never solved). The cause is
structural, not noise:

- **Multi-hole patterns: wrong counts or crashes.** These were checked in the answers,
  not just in the failure strings.
  - 88 failed multi-hole answers use `rarray`, and every one puts the hole diameter in a
    count slot. This is the slip described in the first report: `plate-002`-style
    `.rarray(36, 26, 8, 4)` builds a 32-hole grid.
  - The circle-pattern crashes call a method that doesn't exist, `Workplane.holes` (a few
    call `Workplane.moved`). No example shows `polarArray`.
  - Box/corners answers usually cut one rectangle through the floor (`cutThruAll` of a
    non-circular profile) or fail in OpenCascade (`StdFail_NotDone`).
- **Brackets: always too deep.** 59 of 60 fail on depth. In 58 of the 59 answers that
  place the upright with `.center(0, y)`, `y` is 0.5–18 mm larger than the correct
  `D/2 - t/2` (median 3 mm), so the upright sticks out past the base. That includes the
  20 single-hole brackets, so the bracket failure has nothing to do with holes.

## 4. Caveats

- **"Solved" is still narrow.** It covers bounding box, hole diameter and hole count
  (model/SPEC.md). Hole positions, walls, fillets and the cutout are not scored.
- **Per-stratum McNemar p-values are uncorrected** for multiple comparisons. Treat them as
  descriptive; the overall test is the one to cite.
- **Same templates as training.** This is in-context few-shot prompting, not weight
  training, and the tasks come from the same five generator templates as the examples.
  These results are not evidence of generalisation beyond cad-spec-1.0.

## 5. Reproduce

```bash
export GAUGE_CAD_PYTHON=/path/to/python-with-cadquery
D=model/data/heldout-seed1-n300.json
python model/benchmark.py --data $D --mock oracle            # 300/300
python model/benchmark.py --data $D --mock wrong             # 0/300
python model/benchmark.py --model qwen3.5:9b-q4_K_M --data $D --num-predict 4096 \
    --fewshot 5 --train-data model/data/synthetic-seed0-n100.json \
    --out docs/results/phase4-heldout300-fewshot5-2026-11-14.json
python model/benchmark.py --model qwen3.5:9b-q4_K_M --data $D --num-predict 4096 \
    --out docs/results/phase4-heldout300-baseline-2026-11-14.json
```

The few-shot arm took 37 min. Each run logs every task to `<out>.progress.jsonl` (or
`--log`), and `--resume` continues an interrupted run.
